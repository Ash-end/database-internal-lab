## 一、为什么用二进制？（设计哲学）

同一条记录（key=user:1001, value=Tom）：**JSON 36 字节，二进制 28 字节**。
JSON 的钱花在字段名、引号、括号这些元数据上；二进制只存"长度+内容"。

> [!quote] 三个理由
> 1. **紧凑**：不存字段名，存位置（第几个字节是什么，事先约好）。
> 2. **可算偏移**：长度已知，切片一次到位，不用扫描找边界。
> 3. **可验算**：尾巴带校验和，坏了认得出。

为什么不用 pickle？Python 专有（换语言读不了）、能执行任意代码（收坏文件=中招）、
体积大。数据库要的是**跨语言、透明、可控**的格式。

## 二、记录长什么样？（v1 格式）

```
+--------+---------+--------+----------+----------+-----+-------+-------+
| magic  | version | optype | key_len  | val_len  | key | value | crc32 |
| 2B     | 1B      | 1B     | u32BE    | u32BE    | ... | ...   | u32BE |
+--------+---------+--------+----------+----------+-----+-------+-------+
```

实测解剖（key=ab, value=XY，共 20 字节）：

```
hex：4d4b 01 01 00000002 00000002 6162 5859 c33d044
     ~~~~ ~~ ~~ ~~~~~~~~ ~~~~~~~~ ~~~~ ~~~~ ~~~~~~~
     MK   v1 PUT key长=2 val长=2  ab   XY   crc32
```

- magic `MK`：文件身份证，走错文件秒发现。
- version：以后改格式，新老 reader 靠它分流（Cassandra 甚至写文件名里）。
- optype：1=PUT，2=DELETE（墓碑，val_len=0）。
- 空 value `b""` 合法：有记录但值是空 ≠ 没有记录。

## 三、长度前缀（Pascal 式）

```python
# 存：先写长（4 字节），再写内容
# 读：先读长 n，再切 n 字节 → O(1)，一次到位
```

对比 C 语言 `\0` 结尾：每次现找 0，O(n)；内容里还不能有 0。
实测：`b'a\x00b'`（中间带 0）存取完整——长度前缀不在乎内容是啥。

## 四、大小端（多字节整数的字节顺序）

`0x01020304` 存成 4 字节：

```
大端 BE：01 02 03 04（高位在前，好读，网络惯例）→ 我们选它
小端 LE：04 03 02 01（低位在前，x86 内存序）
```

规则只有一条：**编解码用同一种**。`struct` 的 `>`（BE）和 `<`（LE）别混。

## 五、校验（检错，不纠错）

- 写时对 magic..value 算 crc32 存尾；读时重算比对。
- 实测改 1 个 bit：存 `0xb8e8c1d9` vs 算 `0x7442c147` → 拒收。
- 教材区分：checksum（求和/XOR，只能抓单 bit）vs CRC（抓连续多 bit 坏，存盘主流）。
- CRC **不是安全机制**：防手滑断电，不防黑客（防篡改要用密码学哈希）。

## 六、截断认得出（D10 恢复的前菜）

长度头说要 117 字节，实际只剩 114 → **尾部没写完**，报截断。
恢复时就靠这个认"最后完整边界"：完整之前的全要，残尾处理掉再写。

## 七、偏移链（日志扫描雏形）

`decode_record` 返回 `next_offset`：一条的终点是下一条的起点。
多条连着解 = 日志扫描，MiniKV 启动重建索引就这么走（D9/D10）。

## 八、加深篇（教材 49–50、61–66 页，演示 7–10）

### 8.1 位打包：1 字节当 8 个开关

```python
IS_LEAF, HAS_VALUES, HAS_OVERFLOW = 0x01, 0x02, 0x04  # 每个值只有 1 个 bit 是 1
flags = 0
flags |= HAS_OVERFLOW   # 打开：或运算置位 → 0b00000101
flags |= (1 << 0)       # 同上另一种写法
(flags & HAS_OVERFLOW) != 0   # 查：True；查 HAS_VALUES → False
flags &= ~HAS_OVERFLOW  # 关闭：与上取反清零 → 0b00000001
```

页头常用这招：是否叶页、值是否变长、有无溢出页，3 个开关塞 1 字节。
记住三件套：**开用或，关用与非，查用与**。

### 8.2 变长整数：小数小身板

LEB128：每字节 7 位数据 + 1 位"后面还有吗"。
实测：`42 → 2a`（1 字节，u32 要 4 字节）；`300000 → 3 字节`；都能解回。
代价：长度不固定，算偏移要逐个解。我们首版选定长 u32 保简单——
**简单优先，优化等真瓶颈再说**（D9 定格式时回看）。

### 8.3 浮点存的是近似值

double 按 IEEE 754 存符号/指数/尾数。实测：`0.1 + 0.2 = 0.30000000000000004 ≠ 0.3`。
结论：**钱用整数分存，不用 float**；accuracy 这种 0–1 展示值记得 ROUND。

### 8.4 大小端错配实证

key 长 2 存成大端 `00 00 00 02`；按小端误读 = **33554432**。
我们先验长度（>1024 直接毙），所以报 CorruptionError 而不是去切 32GB 内存。
这就是"没读内容先算账"的意义：**长度头是攻击面，先验后用**。

### 8.5 页头、魔法数、溢出页（第 4 章 61–66 页选读）

- **页头**：flag（页面内容/布局）+ cell 数 + 空闲区上下界。
  PG 存页大小和版本，InnoDB 存堆记录数和层级，SQLite 存 cell 数和最右指针。
- **魔法数**：`50 41 47 45` = ASCII "PAGE"。随机位置撞上它的概率极低，
  读时对一下就知道页有没有对齐、文件走没走错（我们的 `MK` 同理）。
- **兄弟链**：叶层左右拉手，范围扫描不用回爹；代价是分裂合并多改一处（Blink 树才要）。
- **溢出页**：值太大一页装不下，主体放页里，多的串到溢出页（链表）。
  我们的 MAX_VALUE_LEN = 1MB 就是"超过就拒收，不玩溢出页"的简化。

### 8.6 槽页一分钟（Tom、Leslie、Ron）

教材例子：页里按**插入顺序**堆 cell（Tom 到、Leslie 到），另有一张**指针表**按字母序排
（Leslie、Tom）。新来 Ron：cell 往空闲处一堆，只把指针插进排序表（Leslie、Ron、Tom）。
好处：cell 不用搬家（删改只动指针，NULL 掉指针就算删），二分照样能用。
我们的日志是追加写，用不上槽页；但"**数据不动，只改索引**"的思想，和 keydir 一模一样。

### B1. 位打包：8 盏灯

```python
flags = 0b00000000            # 全灭
flags = flags | 0b00000001    # 开灯0 → 0b00000001
flags = flags | 0b00000100    # 开灯2 → 0b00000101
(flags & 0b00000100) != 0     # 查灯2 → True；查灯1 → False
flags = flags & ~0b00000100   # 关灯2 → 0b00000001（专灭这一盏）
```

### B2. 变长整数：逐个数看字节

```
0 → 00（1B）  1 → 01（1B）  42 → 2a（1B）  127 → 7f（1B）
128 → 8001（2B）  300 → ac02（2B）  300000 → e0a712（3B）
```

300 手算：二进制 100101100，低 7 位 `0101100` + 续位 1 = `10101100`(ac)，
高 2 位 `0000010` + 续位 0 = `00000010`(02)。程序输出一致。

### B3. 浮点

```python
0.1 + 0.2 = 0.30000000000000004   # 实测
10 + 20 = 30                       # 分精确
```

### B4. 大小端错配 + JSON 误投

```python
bytes([0,0,0,2]) 按 BE 读 = 2（对）；按 LE 读 = 33554432（错）
decode_record(b'{"key": "x"}')
# CorruptionError: 标识错：b'{"' 不是 b'MK'（走错文件或已损坏）
```

### B5. 魔法数

头两字节 `4d4b = b'MK'`，对上放行。书里 `50 41 47 45` = "PAGE"，同理。

### B6. 槽页三人行

```python
cells = ['Tom', 'Leslie']          # 插入序：谁先到谁在前
order → ['Leslie', 'Tom']          # 逻辑序：按字母排
# Ron 来了：
```
