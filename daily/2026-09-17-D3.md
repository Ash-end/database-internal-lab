## 一、聚合是什么？（小白版）

**一句话：聚合 = 先分组，再对每组算一个数。**

生活类比：老师算成绩。
- 全班 50 人，先按**班级**分组（一班、二班）。
- 对每组算**平均分**：一班 85，二班 78。
- 50 行原始成绩 → 2 行统计结果。**行数变少了，信息变浓了。**

```sql
SELECT datasets.name, COUNT(runs.id)   -- 每组算：名字 + run 数
FROM datasets
JOIN runs ON runs.dataset_id = datasets.id
GROUP BY datasets.name;                -- 按 dataset 分组
-- 输出：(DemoRF, 3)、(DemoRadar, 2)
-- 5 个 run → 2 行统计
```

### 1.1 常用聚合函数

| 函数 | 作用 | 例子 | 结果 |
|------|------|------|------|
| `COUNT(*)` | 数行数（含 NULL 行） | `SELECT COUNT(*) FROM runs` | 5 |
| `COUNT(列)` | 数非空值个数（跳过 NULL） | 见 q07 | 6 |
| `AVG(列)` | 平均值 | accuracy 平均 | 0.8 |
| `MAX(列)` | 最大值 | 最高 accuracy | 0.91 |
| `MIN(列)` | 最小值 | 最低 loss | 0.21 |
| `SUM(列)` | 求和 | — | — |

> [!warning] 聚合函数自动跳过 NULL
> `AVG`、`MAX`、`COUNT(列)` 都无视 NULL，只有 `COUNT(*)` 数所有行。
> 这就是 q07 两个数不一样的原因（下面细讲）。

### 1.2 WHERE vs HAVING：过滤时机不同

```
FROM → JOIN → WHERE（先筛行）→ GROUP BY（分组）→ HAVING（再筛组）→ SELECT → ORDER BY
```

- **WHERE**：分组**之前**筛掉不要的行（比如只要 completed）。
- **HAVING**：分组**之后**筛掉不要的组（比如只要 run 数 > 2 的 dataset）。

```sql
-- run 数超过 2 个的 dataset
SELECT datasets.name, COUNT(runs.id)
FROM datasets
JOIN runs ON runs.dataset_id = datasets.id
GROUP BY datasets.name
HAVING COUNT(runs.id) > 2;   -- 分完组再筛：DemoRF(3) 留，DemoRadar(2) 掉
-- 输出：(DemoRF, 3)
```

> [!note] 为什么不能写 WHERE COUNT(...) > 2？
> WHERE 执行时还没分组，`COUNT` 根本不存在。筛组的条件只能写 HAVING。

### 1.3 COUNT(*) vs COUNT(列)：q07 的 8 和 6

```sql
SELECT COUNT(*), COUNT(metrics.run_id)
FROM runs
LEFT JOIN metrics ON metrics.run_id = runs.id;
-- 输出：(8, 6)
```

逐行数（LEFT JOIN 先拼出 8 行）：

| run | 拼出几行 | metrics.run_id |
|-----|----------|----------------|
| run 1 | 2 行 | 1、1 |
| run 2 | 2 行 | 2、2 |
| run 3 | 1 行 | NULL |
| run 4 | 2 行 | 4、4 |
| run 5 | 1 行 | NULL |

- `COUNT(*)` = 数行：8 行全数。
- `COUNT(metrics.run_id)` = 数非空值：跳过 2 个 NULL → 6。
- **差的那 2，就是没指标的 run 3、run 5 贡献的空行。**

### 1.4 子查询：把一次查询的结果当条件

```sql
-- accuracy 高于平均 accuracy 的 run
SELECT runs.id
FROM runs
JOIN metrics ON metrics.run_id = runs.id
WHERE metrics.metric_name = 'accuracy'
  AND metrics.metric_value > (
      SELECT AVG(metric_value)       -- 内层先算：平均 = 0.8
      FROM metrics WHERE metric_name = 'accuracy'
  )
ORDER BY runs.id;
-- 输出：(4,)，只有 0.91 > 0.8
```

执行顺序：**先内后外**。内层算出 0.8，外层拿每个 accuracy 跟 0.8 比。

### 1.5 CTE：给子查询起个名字（WITH）

```sql
WITH acc AS (                          -- 先定义一张临时表 acc
    SELECT run_id, metric_value AS accuracy
    FROM metrics WHERE metric_name = 'accuracy'
)
SELECT runs.model, acc.accuracy        -- 再像查普通表一样查它
FROM runs JOIN acc ON acc.run_id = runs.id
ORDER BY runs.id;
-- 输出：(CNN, 0.71)、(ResNet, 0.78)、(CNN, 0.91)
```

CTE vs 子查询：同一个东西，CTE 可读性更高，还能被引用多次。

-- q01
SELECT COUNT(*) FROM runs;

SELECT ROUND(AVG(metric_value), 2) FROM metrics WHERE metric_name = 'accuracy';

WITH acc AS (SELECT run_id, metric_value AS accuracy FROM metrics WHERE metric_name = 'accuracy') SELECT runs.model, acc.accuracy FROM runs JOIN acc ON acc.run_id = runs.id ORDER BY runs.id;

## 三、带注释的代码例子（8 组，可直接运行 `labs/sql/learn_day03.py`）

### 先看数据：三张表原样（D3 与 D2 同一份数据）

**datasets（2 行）：**

| id | name | description |
|----|------|-------------|
| 1 | DemoRF | demo rf dataset |
| 2 | DemoRadar | demo radar dataset |

**runs（5 行）：**

| id | dataset_id | model | seed | status | created_at |
|----|------------|-------|------|--------|------------|
| 1 | 1 | CNN | 0 | completed | 2026-01-01 |
| 2 | 1 | ResNet | 0 | completed | 2026-01-02 |
| 3 | 1 | Transformer | 1 | failed | 2026-01-03 |
| 4 | 2 | CNN | 1 | completed | 2026-01-04 |
| 5 | 2 | ResNet | 2 | running | 2026-01-05 |

**metrics（6 行）：**

| id | run_id | metric_name | metric_value |
|----|--------|-------------|--------------|
| 1 | 1 | accuracy | 0.71 |
| 2 | 2 | accuracy | 0.78 |
| 3 | 4 | accuracy | 0.91 |
| 4 | 1 | loss | 0.52 |
| 5 | 2 | loss | 0.44 |
| 6 | 4 | loss | 0.21 |

**D3 只关心这几个数（先圈出来）：**
- accuracy 只有 3 个：run 1 = 0.71、run 2 = 0.78、run 4 = 0.91（run 3、run 5 没有）。
- 每个 dataset 几个 run：DemoRF ← run 1、2、3（3 个）；DemoRadar ← run 4、5（2 个）。
- 每个 run 几条 metric：run 1 = 2 条、run 2 = 2 条、run 3 = 0 条、run 4 = 2 条、run 5 = 0 条。

下面每道题的代码，都是从这三张表里**圈数、分组、算数**。

### 例 1：COUNT(*) 数行数

```sql
SELECT COUNT(*) FROM runs;
-- 输出：5
-- 讲解：runs 表 5 行。* 意思是“整行”，整行一定存在，所以全数。
```

### 例 2：GROUP BY——5 行变 2 行

```sql
-- 先看分组前：JOIN 拼出 5 行
SELECT datasets.name, runs.id
FROM datasets
JOIN runs ON runs.dataset_id = datasets.id
ORDER BY datasets.name, runs.id;
-- 输出：
-- (DemoRF, 1)、(DemoRF, 2)、(DemoRF, 3)
-- (DemoRadar, 4)、(DemoRadar, 5)
-- 讲解：DemoRF 带着 run 1、2、3；DemoRadar 带着 run 4、5。

-- 再分组计数：5 行变 2 行
SELECT datasets.name, COUNT(runs.id)
FROM datasets
JOIN runs ON runs.dataset_id = datasets.id
GROUP BY datasets.name
ORDER BY datasets.name;
-- 输出：(DemoRF, 3)、(DemoRadar, 2)
-- 讲解：聚合查询行数变少，信息变浓。
```

### 例 3：AVG 的浮点灰尘与 ROUND

```sql
-- 裸 AVG：理论上 (0.71+0.78+0.91)/3 = 0.8，实际：
SELECT AVG(metric_value) FROM metrics WHERE metric_name = 'accuracy';
-- 输出：0.7999999999999999
-- 讲解：计算机用二进制存小数，算出来带一尾巴灰尘。实测为证。

-- ROUND 修到 2 位小数：
SELECT ROUND(AVG(metric_value), 2) FROM metrics WHERE metric_name = 'accuracy';
-- 输出：0.8
-- 讲解：凡是 AVG 后面要比较、要展示，都包一层 ROUND(..., 2)。工程习惯。

-- 分组平均：
SELECT runs.model, ROUND(AVG(metrics.metric_value), 2)
FROM runs
JOIN metrics ON metrics.run_id = runs.id
WHERE metrics.metric_name = 'accuracy'
GROUP BY runs.model
ORDER BY runs.model;
-- 输出：(CNN, 0.81)、(ResNet, 0.78)
-- 讲解：CNN 组 (0.71+0.91)/2 = 0.81。Transformer 在 metrics 里没有 accuracy 行，
-- INNER JOIN 把它扔了，所以结果里没有 Transformer。

-- MAX 直接挑存值，不做算术，没灰尘：
SELECT MAX(metric_value) FROM metrics WHERE metric_name = 'accuracy';
-- 输出：0.91
```

### 例 4：HAVING——反面教材与正面教材

```sql
-- 反面：WHERE 里写 COUNT，直接报错
SELECT datasets.name FROM datasets
JOIN runs ON runs.dataset_id = datasets.id
WHERE COUNT(runs.id) > 2
GROUP BY datasets.name;
-- 报错：misuse of aggregate: COUNT()
-- 讲解：WHERE 执行时还没分组，COUNT 不存在。实测为证。

-- 正面：HAVING 在分组后筛组
SELECT datasets.name, COUNT(runs.id)
FROM datasets
JOIN runs ON runs.dataset_id = datasets.id
GROUP BY datasets.name              -- 先分组：DemoRF(3)、DemoRadar(2)
HAVING COUNT(runs.id) > 2;          -- 分完组再筛：只要 run 数 > 2 的组
-- 输出：(DemoRF, 3)
-- 记住顺序：WHERE（筛行）→ GROUP BY（分组）→ HAVING（筛组）。
```

### 例 5：COUNT(*) = 8，COUNT(列) = 6

```sql
-- 先看 LEFT JOIN 拼出哪 8 行：
SELECT runs.id, metrics.run_id, metrics.metric_name
FROM runs
LEFT JOIN metrics ON metrics.run_id = runs.id
ORDER BY runs.id, metrics.metric_name;
-- 输出 8 行：
-- (1, 1, accuracy)、(1, 1, loss)
-- (2, 2, accuracy)、(2, 2, loss)
-- (3, None, None)                  ← 空行
-- (4, 4, accuracy)、(4, 4, loss)
-- (5, None, None)                  ← 空行

SELECT COUNT(*),                -- 数行：8 行全数
       COUNT(metrics.run_id)    -- 数非空值：跳过 2 个 NULL，只剩 6
FROM runs
LEFT JOIN metrics ON metrics.run_id = runs.id;
-- 输出：(8, 6)
-- 讲解：差的 2 就是 run 3、run 5 贡献的空行。
-- 规律：AVG/MAX/COUNT(列) 都跳过 NULL，只有 COUNT(*) 数所有行。
```

### 例 6：子查询——先内后外

```sql
-- 内层先算（独立查询）：平均 accuracy
SELECT AVG(metric_value) FROM metrics WHERE metric_name = 'accuracy';
-- 输出约 0.8。内层先出结果，外层拿它当尺子。

-- 外层再比：
SELECT runs.id
FROM runs
JOIN metrics ON metrics.run_id = runs.id
WHERE metrics.metric_name = 'accuracy'
  AND metrics.metric_value > (
      SELECT AVG(metric_value)
      FROM metrics WHERE metric_name = 'accuracy'
  )
ORDER BY runs.id;
-- 输出：(4,)。0.71 比不过，0.78 比不过，只有 0.91 通过。
-- 子查询 = 把一次查询的结果当条件用。
```

### 例 7：CTE——给子查询起名字

```sql
WITH acc AS (                         -- 先定义一张临时表 acc
    SELECT run_id, metric_value AS accuracy
    FROM metrics WHERE metric_name = 'accuracy'
)
SELECT runs.model, acc.accuracy       -- 再像查普通表一样查它
FROM runs JOIN acc ON acc.run_id = runs.id
ORDER BY runs.id;
-- 输出：(CNN, 0.71)、(ResNet, 0.78)、(CNN, 0.91)
-- 讲解：和子查询同一个意思，可读性更高，还能被引用多次。
-- CNN 出现两次是因为 run 1 和 run 4 都是 CNN。
```

### 例 8：LEFT JOIN + GROUP BY——含 0 的统计

```sql
SELECT runs.id, COUNT(metrics.id)
FROM runs
LEFT JOIN metrics ON metrics.run_id = runs.id
GROUP BY runs.id
ORDER BY runs.id;
-- 输出：(1, 2)、(2, 2)、(3, 0)、(4, 2)、(5, 0)
-- 讲解：run 3、run 5 的组里只有 NULL，COUNT(列) 跳过 NULL，所以是 0 而不是 1。
-- 想统计“含零”的分布，LEFT JOIN + GROUP BY 是标准写法。
```
