## 一、为什么拆表？（小白版）

### 1.1 先看单表会怎么烂掉

假设我们不拆表，把 dataset 的描述也塞进每一行：

```
id | model  | dataset   | dataset_description | accuracy
1  | CNN    | DemoRF    | demo rf dataset     | 0.71
2  | ResNet | DemoRF    | demo rf dataset     | 0.78
3  | Transf | DemoRF    | demo rf dataset     | NULL
```

`"demo rf dataset"` 这个**事实**存了 3 遍。会烂在三个地方：

**烂法 1：改漏一行（更新异常）**
老板说描述改成 `"demo rf dataset v2"`。你改了第 1、2 行，漏了第 3 行。
现在数据库里同一个 DemoRF 有两种描述——到底哪个是对的？没人知道了。

**烂法 2：没 run 就存不下 dataset（插入异常）**
新来一个数据集 `DemoNew`，还没跑过任何实验。单表里每一行都必须是一个 run，
`DemoNew` 没有 run 就没有行可写——一个真实存在的数据集，数据库里存不下。

**烂法 3：删光 run 就丢了 dataset（删除异常）**
把 DemoRF 的 3 个 run 全删了，`description` 跟着一起消失。
数据集本身还存在，但数据库把它"忘"了。

> [!quote] 核心思想
> **一个事实只存一次，其他地方引用它。**
> dataset 的描述只在 `datasets` 表存一行，`runs` 里只存一个编号 `dataset_id`。

### 1.2 一对多：父子关系

```
datasets (1) ───< runs (N) ───< metrics (N)
```

读作：**一个 dataset 有多个 run，一个 run 有多个 metric**。反过来不行：
一个 run 只属于一个 dataset（`dataset_id` 只有一个格子，只能填一个编号）。

生活类比：**一个班级有多个学生**。
- `班级表`：一班、二班（只存一次）
- `学生表`：张三（一班）、李四（一班）、王五（二班)
- 学生表里的"班级"一列，填的不是"高一一班教室在三楼……"，只填一个编号 `class_id = 1`。

我们的表就是这样：

```
datasets: 1=DemoRF, 2=DemoRadar        ← 事实只存一次
runs: 1→dataset 1, 2→dataset 1, 4→dataset 2   ← 只存编号
```

### 1.3 主键：每行的身份证号

**主键 PK = 唯一标识本表每一行的列。**

为什么需要？因为其他列都可能重复：
- `model` 会重复（好几个 CNN）
- `status` 会重复（好几个 completed）
- 只有 `id` 不重复，所以用它当身份证。

生活类比：**学号**。张三李四名字可能重复，但学号一人一个。
点名时喊"学号 1001"，全班只有一个站起来——这就是主键的作用：**精确指向一行**。

规则两条，用身份证类比就懂：
1. **不能为空**：不能有个"没有身份证号的人"，否则找不到他。
2. **不能重复**：不能两个人共用一个身份证号，否则分不清。

这就是为什么"重复主键被拒绝"：`INSERT id=1` 两次，第二次报错。

### 1.4 外键：指向别人身份证的编号

**外键 FK = 子表里存的、指向父表主键的编号。**

- `runs.dataset_id = 1` 的意思是："我这个 run 用的数据集，去 `datasets` 表查 `id = 1` 那行"。
- 它本身不是数据，只是一个**指针 / 引用 / 门牌号**。

生活类比：**学生证上的"班级编号"**。
学生证不印整个班级的介绍，只印 `班级=1`。想知道班级详情，拿着 1 去班级表查。

外键规则也只有一条：**填的编号，父表里必须真实存在**。
`dataset_id = 999` 被拒绝，就是因为 `datasets` 里没有 `id = 999`——
好比学生证上写"X 班"，学校里根本没有这个班，这证就是废纸，数据库不让存。

这就是为什么"非法外键被拒绝"：`FOREIGN KEY constraint failed`。

### 1.5 其他约束：一句话版

| 约束 | 一句话 | 本例 |
|------|--------|------|
| `UNIQUE` | 同一组合不能出现两次 | 同一个 run 不能有两个 `accuracy` |
| `CHECK` | 值必须在允许范围内 | `status` 只能是 completed/running/failed |
| `NOT NULL` | 这个格子不许空着 | `model` 不能为空 |

### 1.6 为什么外键还要手动打开？

SQLite 有个坑：**外键检查默认是关的**。
你在建表时写了 `REFERENCES`，它只是"登记了一下关系"，不检查。
每个新连接必须执行一次：

```sql
PRAGMA foreign_keys = ON;
```

然后查一下返回值是不是 1，确认真的打开了。
我们的实验里 `foreign_keys = 1`，所以非法外键才会被抓住。

## 二、JOIN：把拆开的表拼回去（小白版）

**一句话：JOIN 就是"拿着编号去另一张表查详情"。**

学生证上写着 `班级=1`，你拿着 1 去班级表找到"一班"，把两行的信息拼成一行。
SQL 里这个"拿着编号去查"的动作就叫 JOIN。

### 2.1 INNER JOIN：两边都对得上才要

```sql
SELECT runs.id, runs.model, datasets.name
FROM runs
JOIN datasets ON runs.dataset_id = datasets.id
ORDER BY runs.id;
```

逐字翻译：
- `FROM runs`：从 run 表出发，一行一行看
- `JOIN datasets`：每看一个 run，都去 dataset 表查一次
- `ON runs.dataset_id = datasets.id`：查的方法——run 的编号等于 dataset 的身份证号
- 拿 run 1 举例：`dataset_id = 1`，去 datasets 找到 `id = 1`（DemoRF)，拼成一行：`(1, CNN, DemoRF)`
- 拿 run 4 举例：`dataset_id = 2`，找到 `id = 2`（DemoRadar)，拼成：`(4, CNN, DemoRadar)`

`JOIN` 不写前缀默认就是 INNER JOIN：**两边都匹配才保留**。
run 的 `dataset_id` 个个都有爹（外键保证的），所以 5 个 run 全保留。

### 2.2 ON 和 WHERE 分工不同

- **ON**：说"怎么拼"。`ON runs.dataset_id = datasets.id` = 拼表规则。
- **WHERE**：拼完之后"筛哪些行"。`WHERE runs.status = 'completed'` = 只要完成的。

q02 就是 q01 拼完之后再筛一遍，所以 run 3（failed）、run 5（running）被筛掉，
剩下 1、2、4。

### 2.3 LEFT JOIN：左表一个都不能少

INNER JOIN 有个狠心之处：**对不上就扔掉**。q04 就是例子：

```sql
SELECT runs.id, metrics.metric_value
FROM runs
JOIN metrics ON metrics.run_id = runs.id
WHERE metrics.metric_name = 'accuracy'
```

run 3、run 5 在 metrics 表里根本没有行，对不上，直接消失。结果只有 1、2、4。

但有时候你恰恰想找"消失的那些"——比如"哪些 run 还没出指标？"
这时用 LEFT JOIN：

```sql
SELECT runs.id, runs.model
FROM runs
LEFT JOIN metrics ON metrics.run_id = runs.id
WHERE metrics.run_id IS NULL
ORDER BY runs.id;
```

分三步理解：

**第 1 步：LEFT JOIN 先拼，左表全保留**
```
run 1 → 对上 2 条 metric（accuracy、loss），变成 2 行
run 2 → 对上 2 条，变成 2 行
run 3 → 对不上，保留 run，右边全填 NULL → (3, Transformer, NULL, NULL)
run 4 → 对上 2 条，变成 2 行
run 5 → 对不上，保留，右边填 NULL → (5, ResNet, NULL, NULL)
```

**第 2 步：WHERE metrics.run_id IS NULL 只留右边是空的**
只剩 run 3、run 5——正是没有指标的那两个。

**第 3 步：SELECT 只拿左表列**
`(3, Transformer)`、`(5, ResNet)`。

> [!tip] 固定套路
> **LEFT JOIN + `WHERE 右表.列 IS NULL` = 找孤儿行。**
> 以后凡是"找出没有订单的客户""找出没有评论的文章"，都是这个套路。

### 2.4 三表 JOIN：连查两次

```sql
SELECT runs.id, runs.model, datasets.name, metrics.metric_value
FROM runs
JOIN datasets ON runs.dataset_id = datasets.id   -- 第一次：往上查爹（拿名字）
JOIN metrics ON metrics.run_id = runs.id         -- 第二次：往下查娃（拿指标）
WHERE metrics.metric_name = 'accuracy'
ORDER BY runs.id;
```

以 run 2 为例：
1. `dataset_id = 1` → 查到 DemoRF
2. `id = 2` → 在 metrics 找到 `(2, accuracy, 0.78)`
3. 拼成：`(2, ResNet, DemoRF, 0.78)`

q08 反过来：从 `metrics` 出发，同时往上连 `runs` 再连 `datasets`，
查 run 1 的全部指标。方向无所谓，`ON` 写对就行。

### 2.5 一张图记住

```
INNER JOIN：  只留"两边都有"的       → 查"有指标的 run"
LEFT JOIN：   左边全留，右边缺失补 NULL → 查"没指标的 run"
ON：          怎么拼（外键 = 主键）
WHERE：       拼完筛哪些
```

## 六、带注释的代码例子（8 个，可直接运行 `labs/sql/learn_day02.py`）

### 例 1：主键——身份证号不能重复

```python
import sqlite3
conn = sqlite3.connect(':memory:')
conn.execute('PRAGMA foreign_keys = ON')
# ...先加载 seed_day02.sql 建表+数据...

try:
    # id=1 已经存在，再插一次 id=1，看数据库拦不拦
    conn.execute(
        "INSERT INTO datasets (id, name, description) VALUES (1, 'Dup', 'dup')"
    )
except sqlite3.IntegrityError as e:
    # IntegrityError = 完整性错误，意思是“这条数据破坏了表的规矩”
    print('被拒绝:', e)
    # 输出：UNIQUE constraint failed: datasets.id
    # 讲解：两个人不能共用一个身份证号，所以 id=1 只能有一行。
```

### 例 2：外键——编号必须真实存在

```python
try:
    # dataset_id=999 在 datasets 表里根本不存在
    conn.execute(
        "INSERT INTO runs (id, dataset_id, model, seed, status, created_at)"
        " VALUES (99, 999, 'CNN', 0, 'completed', '2026-09-17')"
    )
except sqlite3.IntegrityError as e:
    print('被拒绝:', e)
    # 输出：FOREIGN KEY constraint failed
    # 讲解：学生证上写了个不存在的班级，学校不认这张证。

# 合法的外键能插进去：dataset_id=1 真实存在
conn.execute(
    "INSERT INTO runs (id, dataset_id, model, seed, status, created_at)"
    " VALUES (90, 1, 'CNN', 9, 'completed', '2026-09-17')"
)
```

### 例 3：INNER JOIN——拿着编号去查详情

```sql
SELECT runs.id, runs.model, datasets.name  -- 要：run编号、模型、数据集名
FROM runs                                   -- 从 runs 出发，一行一行看
JOIN datasets                               -- 每看一个 run，都去 datasets 查一次
  ON runs.dataset_id = datasets.id          -- 怎么查：run的编号 = dataset的身份证号
ORDER BY runs.id;
-- 输出：
-- (1, 'CNN', 'DemoRF')
-- (2, 'ResNet', 'DemoRF')
-- (3, 'Transformer', 'DemoRF')
-- (4, 'CNN', 'DemoRadar')
-- (5, 'ResNet', 'DemoRadar')
-- 讲解：run 1 的 dataset_id=1，找到 DemoRF，拼成 (1, CNN, DemoRF)。
```

### 例 4：INNER JOIN 对不上就消失

```sql
SELECT runs.id, runs.model                  -- 只要 run 的信息
FROM runs
JOIN metrics                                -- 去 metrics 表找指标
  ON metrics.run_id = runs.id               -- 指标的行号 = run 的身份证号
WHERE metrics.metric_name = 'accuracy'      -- 只要 accuracy 这一种指标
ORDER BY runs.id;
-- 输出：(1, 'CNN')、(2, 'ResNet')、(4, 'CNN')
-- 讲解：run 3、run 5 在 metrics 里没有行，对不上，直接消失。
-- 这就是 INNER：两边都匹配才保留。
```

### 例 5：LEFT JOIN——对不上也不扔，右边填 NULL

```sql
SELECT runs.id, runs.model, metrics.metric_name, metrics.metric_value
FROM runs
LEFT JOIN metrics                           -- LEFT：runs 的行全部保留
  ON metrics.run_id = runs.id               -- 对得上就拼上，对不上右边填 NULL
WHERE runs.id IN (2, 3)                     -- 只看 run 2（有指标）和 run 3（没指标）对比
ORDER BY runs.id, metrics.metric_name;
-- 输出：
-- (2, 'ResNet', 'accuracy', 0.78)
-- (2, 'ResNet', 'loss', 0.44)
-- (3, 'Transformer', None, None)   ← 行还在，右边全是 NULL
-- 讲解：None 就是“查无此人”的标记。
```

### 例 6：LEFT JOIN + IS NULL——找孤儿行（固定套路）

```sql
SELECT runs.id, runs.model
FROM runs
LEFT JOIN metrics                           -- 第1步：左表全保留，缺失补 NULL
  ON metrics.run_id = runs.id
WHERE metrics.run_id IS NULL                -- 第2步：只留右边是空的（= 没指标的）
ORDER BY runs.id;
-- 输出：(3, 'Transformer')、(5, 'ResNet')
-- 讲解：run 3（failed）、run 5（running）没有指标，被筛出来。
-- 以后“找没订单的客户”“找没评论的文章”，全是这个写法。
```

### 例 7：ON vs WHERE——ON 管怎么拼，WHERE 管留哪些

```sql
SELECT runs.id, runs.model, datasets.name
FROM runs
JOIN datasets
  ON runs.dataset_id = datasets.id          -- ON：管“怎么拼”（拼表规则）
WHERE runs.status = 'completed'             -- WHERE：管“拼完留哪些”（过滤）
ORDER BY runs.id;
-- 输出：(1, 'CNN', 'DemoRF')、(2, 'ResNet', 'DemoRF')、(4, 'CNN', 'DemoRadar')
-- 讲解：先按 ON 拼出 5 行，再按 WHERE 筛掉 run 3 和 run 5。
```

### 例 8：三表 JOIN——从中间表出发，两边各查一次

```sql
SELECT runs.id, runs.model, datasets.name, metrics.metric_value
FROM runs
JOIN datasets                               -- 第1次：往上查爹，拿数据集名
  ON runs.dataset_id = datasets.id
JOIN metrics                                -- 第2次：往下查娃，拿指标值
  ON metrics.run_id = runs.id
WHERE metrics.metric_name = 'accuracy'      -- 只要 accuracy
ORDER BY runs.id;
-- 输出：
-- (1, 'CNN', 'DemoRF', 0.71)
-- (2, 'ResNet', 'DemoRF', 0.78)
-- (4, 'CNN', 'DemoRadar', 0.91)
-- 讲解：以 run 2 为例，dataset_id=1 查到 DemoRF；
-- id=2 查到 accuracy 0.78；拼成 (2, ResNet, DemoRF, 0.78)。
```

## 七、问答记录（2026-09-17）

**问：`INSERT INTO runs (id, dataset_id, ...) VALUES (99, 999, ...)` 是不是往 runs 表插一行？**
答：是。括号里第一组是**列名**（往哪几个格子填），`VALUES` 里是**值**（填什么），位置一一对应：
`id←99, dataset_id←999, model←'CNN', seed←0, status←'completed', created_at←日期`。

**问：为什么一行里既有 id 又有 dataset_id？**
答：它们是两种完全不同的编号：
- `id = 99`：**本行的身份证号**（主键），说"我是谁"——第 99 号 run。
- `dataset_id = 999`：**指向别人身份证的编号**（外键），说"我属于哪个 dataset"——去 datasets 表找 id=999。
- 这行被拒绝正是因为 datasets 里没有 999，引用了不存在的爹。

**问：`JOIN metrics ON metrics.run_id = runs.id` 里 JOIN 是干什么的？**
答：JOIN = 拿着编号去另一张表查详情再拼成一行。
`ON` 后面是查法：`metrics.run_id = runs.id`，即"指标单上的 run 编号等于 run 的身份证号就拼在一起"。
INNER JOIN 只留两边都对得上的行，所以没指标的 run 3、run 5 直接消失。

**问：`LEFT JOIN metrics ON metrics.run_id = runs.id` 是什么意思？**
答：LEFT = 左表（FROM 后面的 runs）一个都不能少。
对得上就拼，对不上右边全填 NULL（人还在，成绩单是空的）。
再配 `WHERE metrics.run_id IS NULL`，就筛出"没指标的 run"——找孤儿行套路。

## 八、三张表长什么样（先看数据，再看代码）

### datasets 表：只有 2 行（事实只存一次）

| id | name | description |
|----|------|-------------|
| 1 | DemoRF | demo rf dataset |
| 2 | DemoRadar | demo radar dataset |

### runs 表：5 行，注意 dataset_id 列

| id | dataset_id | model | seed | status | created_at |
|----|------------|-------|------|--------|------------|
| 1 | 1 | CNN | 0 | completed | 2026-01-01 |
| 2 | 1 | ResNet | 0 | completed | 2026-01-02 |
| 3 | 1 | Transformer | 1 | failed | 2026-01-03 |
| 4 | 2 | CNN | 1 | completed | 2026-01-04 |
| 5 | 2 | ResNet | 2 | running | 2026-01-05 |

读法：run 1 的 `dataset_id = 1`，意思是"去 datasets 表找 id=1"→ DemoRF。
run 4 的 `dataset_id = 2` → DemoRadar。

### metrics 表：6 行，注意 id 和 run_id 是两列

| id | run_id | metric_name | metric_value |
|----|--------|-------------|--------------|
| 1 | 1 | accuracy | 0.71 |
| 4 | 1 | loss | 0.52 |
| 2 | 2 | accuracy | 0.78 |
| 5 | 2 | loss | 0.44 |
| 3 | 4 | accuracy | 0.91 |
| 6 | 4 | loss | 0.21 |

读法（关键！两列别混）：
- `id`：本行的身份证号（第几条指标记录）。
- `run_id`：指向爹的编号（这条指标属于哪个 run）。
- 第 1 行：`id=1, run_id=1` 意思是"第 1 条指标记录，属于 run 1，指标名 accuracy，值 0.71"。
- run 3、run 5 在这张表里**一次都没出现**——它们没有指标。

### 逐行推演 q01：基础拼表

```sql
SELECT runs.id, runs.model, datasets.name
FROM runs
JOIN datasets ON runs.dataset_id = datasets.id
ORDER BY runs.id;
```

数据库一行一行走：

| 看到 run | dataset_id | 去 datasets 找 id= | 找到 | 拼成一行 |
|----------|------------|--------------------|------|----------|
| run 1 CNN | 1 | 1 | DemoRF | (1, CNN, DemoRF) |
| run 2 ResNet | 1 | 1 | DemoRF | (2, ResNet, DemoRF) |
| run 3 Transformer | 1 | 1 | DemoRF | (3, Transformer, DemoRF) |
| run 4 CNN | 2 | 2 | DemoRadar | (4, CNN, DemoRadar) |
| run 5 ResNet | 2 | 2 | DemoRadar | (5, ResNet, DemoRadar) |

输出就是这 5 行。`ON` 干的事就是中间两列：拿编号找人。

### 逐行推演 q06：LEFT JOIN 找孤儿

```sql
SELECT runs.id, runs.model
FROM runs
LEFT JOIN metrics ON metrics.run_id = runs.id
WHERE metrics.run_id IS NULL
ORDER BY runs.id;
```

第 1 步先拼（左表 5 个 run 全保留）：

| 看到 run | 去 metrics 找 run_id= | 找到几条 | 拼完 |
|----------|----------------------|----------|------|
| run 1 | 1 | 2 条（accuracy、loss） | 变成 2 行 |
| run 2 | 2 | 2 条（accuracy、loss） | 变成 2 行 |
| run 3 | 3 | 0 条 | 保留，右边填 NULL |
| run 4 | 4 | 2 条（accuracy、loss） | 变成 2 行 |
| run 5 | 5 | 0 条 | 保留，右边填 NULL |

第 2 步 `WHERE metrics.run_id IS NULL`：只留右边是空的 → run 3、run 5。
输出：`(3, Transformer)`、`(5, ResNet)`。
