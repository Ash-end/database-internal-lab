## 一、为什么拆表？（小白版）

### 1.1 先看单表会怎么烂掉

假设我们不拆表，把 dataset 的描述也塞进每一行：

```
id | model  | dataset   | dataset_description | accuracy
1  | CNN    | DemoRF    | demo rf dataset     | 0.71
2  | ResNet | DemoRF    | demo rf dataset     | 0.78
3  | Transf | DemoRF    | demo rf dataset     | NULL
```

`"demo rf dataset"` 这个**事实**存了 3 遍。会烂在三个地方：

**烂法 1：改漏一行（更新异常）**
老板说描述改成 `"demo rf dataset v2"`。你改了第 1、2 行，漏了第 3 行。
现在数据库里同一个 DemoRF 有两种描述——到底哪个是对的？没人知道了。

**烂法 2：没 run 就存不下 dataset（插入异常）**
新来一个数据集 `DemoNew`，还没跑过任何实验。单表里每一行都必须是一个 run，
`DemoNew` 没有 run 就没有行可写——一个真实存在的数据集，数据库里存不下。

**烂法 3：删光 run 就丢了 dataset（删除异常）**
把 DemoRF 的 3 个 run 全删了，`description` 跟着一起消失。
数据集本身还存在，但数据库把它"忘"了。

> [!quote] 核心思想
> **一个事实只存一次，其他地方引用它。**
> dataset 的描述只在 `datasets` 表存一行，`runs` 里只存一个编号 `dataset_id`。

### 1.2 一对多：父子关系

```
datasets (1) ───< runs (N) ───< metrics (N)
```

读作：**一个 dataset 有多个 run，一个 run 有多个 metric**。反过来不行：
一个 run 只属于一个 dataset（`dataset_id` 只有一个格子，只能填一个编号）。

生活类比：**一个班级有多个学生**。
- `班级表`：一班、二班（只存一次）
- `学生表`：张三（一班）、李四（一班）、王五（二班)
- 学生表里的"班级"一列，填的不是"高一一班教室在三楼……"，只填一个编号 `class_id = 1`。

我们的表就是这样：

```
datasets: 1=DemoRF, 2=DemoRadar        ← 事实只存一次
runs: 1→dataset 1, 2→dataset 1, 4→dataset 2   ← 只存编号
```

### 1.3 主键：每行的身份证号

**主键 PK = 唯一标识本表每一行的列。**

为什么需要？因为其他列都可能重复：
- `model` 会重复（好几个 CNN）
- `status` 会重复（好几个 completed）
- 只有 `id` 不重复，所以用它当身份证。

生活类比：**学号**。张三李四名字可能重复，但学号一人一个。
点名时喊"学号 1001"，全班只有一个站起来——这就是主键的作用：**精确指向一行**。

规则两条，用身份证类比就懂：
1. **不能为空**：不能有个"没有身份证号的人"，否则找不到他。
2. **不能重复**：不能两个人共用一个身份证号，否则分不清。

这就是为什么"重复主键被拒绝"：`INSERT id=1` 两次，第二次报错。

### 1.4 外键：指向别人身份证的编号

**外键 FK = 子表里存的、指向父表主键的编号。**

- `runs.dataset_id = 1` 的意思是："我这个 run 用的数据集，去 `datasets` 表查 `id = 1` 那行"。
- 它本身不是数据，只是一个**指针 / 引用 / 门牌号**。

生活类比：**学生证上的"班级编号"**。
学生证不印整个班级的介绍，只印 `班级=1`。想知道班级详情，拿着 1 去班级表查。

外键规则也只有一条：**填的编号，父表里必须真实存在**。
`dataset_id = 999` 被拒绝，就是因为 `datasets` 里没有 `id = 999`——
好比学生证上写"X 班"，学校里根本没有这个班，这证就是废纸，数据库不让存。

这就是为什么"非法外键被拒绝"：`FOREIGN KEY constraint failed`。

### 1.5 其他约束：一句话版

| 约束 | 一句话 | 本例 |
|------|--------|------|
| `UNIQUE` | 同一组合不能出现两次 | 同一个 run 不能有两个 `accuracy` |
| `CHECK` | 值必须在允许范围内 | `status` 只能是 completed/running/failed |
| `NOT NULL` | 这个格子不许空着 | `model` 不能为空 |

### 1.6 为什么外键还要手动打开？

SQLite 有个坑：**外键检查默认是关的**。
你在建表时写了 `REFERENCES`，它只是"登记了一下关系"，不检查。
每个新连接必须执行一次：

```sql
PRAGMA foreign_keys = ON;
```

然后查一下返回值是不是 1，确认真的打开了。
我们的实验里 `foreign_keys = 1`，所以非法外键才会被抓住。

## 二、JOIN：把拆开的表拼回去（小白版）

**一句话：JOIN 就是"拿着编号去另一张表查详情"。**

学生证上写着 `班级=1`，你拿着 1 去班级表找到"一班"，把两行的信息拼成一行。
SQL 里这个"拿着编号去查"的动作就叫 JOIN。

### 2.1 INNER JOIN：两边都对得上才要

```sql
SELECT runs.id, runs.model, datasets.name
FROM runs
JOIN datasets ON runs.dataset_id = datasets.id
ORDER BY runs.id;
```

逐字翻译：
- `FROM runs`：从 run 表出发，一行一行看
- `JOIN datasets`：每看一个 run，都去 dataset 表查一次
- `ON runs.dataset_id = datasets.id`：查的方法——run 的编号等于 dataset 的身份证号
- 拿 run 1 举例：`dataset_id = 1`，去 datasets 找到 `id = 1`（DemoRF)，拼成一行：`(1, CNN, DemoRF)`
- 拿 run 4 举例：`dataset_id = 2`，找到 `id = 2`（DemoRadar)，拼成：`(4, CNN, DemoRadar)`

`JOIN` 不写前缀默认就是 INNER JOIN：**两边都匹配才保留**。
run 的 `dataset_id` 个个都有爹（外键保证的），所以 5 个 run 全保留。

### 2.2 ON 和 WHERE 分工不同

- **ON**：说"怎么拼"。`ON runs.dataset_id = datasets.id` = 拼表规则。
- **WHERE**：拼完之后"筛哪些行"。`WHERE runs.status = 'completed'` = 只要完成的。

q02 就是 q01 拼完之后再筛一遍，所以 run 3（failed）、run 5（running）被筛掉，
剩下 1、2、4。

### 2.3 LEFT JOIN：左表一个都不能少

INNER JOIN 有个狠心之处：**对不上就扔掉**。q04 就是例子：

```sql
SELECT runs.id, metrics.metric_value
FROM runs
JOIN metrics ON metrics.run_id = runs.id
WHERE metrics.metric_name = 'accuracy'
```

run 3、run 5 在 metrics 表里根本没有行，对不上，直接消失。结果只有 1、2、4。

但有时候你恰恰想找"消失的那些"——比如"哪些 run 还没出指标？"
这时用 LEFT JOIN：

```sql
SELECT runs.id, runs.model
FROM runs
LEFT JOIN metrics ON metrics.run_id = runs.id
WHERE metrics.run_id IS NULL
ORDER BY runs.id;
```

分三步理解：

**第 1 步：LEFT JOIN 先拼，左表全保留**
```
run 1 → 对上 2 条 metric（accuracy、loss），变成 2 行
run 2 → 对上 2 条，变成 2 行
run 3 → 对不上，保留 run，右边全填 NULL → (3, Transformer, NULL, NULL)
run 4 → 对上 2 条，变成 2 行
run 5 → 对不上，保留，右边填 NULL → (5, ResNet, NULL, NULL)
```

**第 2 步：WHERE metrics.run_id IS NULL 只留右边是空的**
只剩 run 3、run 5——正是没有指标的那两个。

**第 3 步：SELECT 只拿左表列**
`(3, Transformer)`、`(5, ResNet)`。

> [!tip] 固定套路
> **LEFT JOIN + `WHERE 右表.列 IS NULL` = 找孤儿行。**
> 以后凡是"找出没有订单的客户""找出没有评论的文章"，都是这个套路。

### 2.4 三表 JOIN：连查两次

```sql
SELECT runs.id, runs.model, datasets.name, metrics.metric_value
FROM runs
JOIN datasets ON runs.dataset_id = datasets.id   -- 第一次：往上查爹（拿名字）
JOIN metrics ON metrics.run_id = runs.id         -- 第二次：往下查娃（拿指标）
WHERE metrics.metric_name = 'accuracy'
ORDER BY runs.id;
```

以 run 2 为例：
1. `dataset_id = 1` → 查到 DemoRF
2. `id = 2` → 在 metrics 找到 `(2, accuracy, 0.78)`
3. 拼成：`(2, ResNet, DemoRF, 0.78)`

q08 反过来：从 `metrics` 出发，同时往上连 `runs` 再连 `datasets`，
查 run 1 的全部指标。方向无所谓，`ON` 写对就行。

### 2.5 一张图记住

```
INNER JOIN：  只留"两边都有"的       → 查"有指标的 run"
LEFT JOIN：   左边全留，右边缺失补 NULL → 查"没指标的 run"
ON：          怎么拼（外键 = 主键）
WHERE：       拼完筛哪些
```

```sql
-- q01
SELECT runs.id, runs.model, datasets.name FROM runs JOIN datasets ON runs.dataset_id = datasets.id ORDER BY runs.id;
-- q02
SELECT runs.id, runs.model, datasets.name FROM runs JOIN datasets ON runs.dataset_id = datasets.id WHERE runs.status = 'completed' ORDER BY runs.id;
-- q03
SELECT DISTINCT datasets.name FROM runs JOIN datasets ON runs.dataset_id = datasets.id WHERE runs.model = 'ResNet' ORDER BY datasets.name;

SELECT runs.id, metrics.metric_value FROM runs JOIN metrics ON metrics.run_id = runs.id WHERE metrics.metric_name = 'accuracy' ORDER BY runs.id;
-- q05
SELECT runs.id, runs.model, datasets.name, metrics.metric_value FROM runs JOIN datasets ON runs.dataset_id = datasets.id JOIN metrics ON metrics.run_id = runs.id WHERE runs.status = 'completed' AND metrics.metric_name = 'accuracy' AND metrics.metric_value >= 0.75 ORDER BY runs.id;
-- q06
SELECT runs.id, runs.model FROM runs LEFT JOIN metrics ON metrics.run_id = runs.id WHERE metrics.run_id IS NULL ORDER BY runs.id;
-- q07
SELECT runs.id, runs.model, metrics.metric_value FROM runs JOIN metrics ON metrics.run_id = runs.id WHERE metrics.metric_name = 'loss' ORDER BY runs.id;
-- q08
SELECT datasets.name, metrics.metric_name, metrics.metric_value FROM metrics JOIN runs ON metrics.run_id = runs.id JOIN datasets ON runs.dataset_id = datasets.id WHERE runs.id = 1 ORDER BY metrics.metric_name;
```

## 四、约束验证实验（必须亲手做）

```python
import sqlite3
conn = sqlite3.connect(':memory:')
conn.execute('PRAGMA foreign_keys = ON')
# 加载 seed_day02.sql 建表+数据后，逐条验证：

# 1. 重复主键被拒绝
# INSERT INTO datasets (id, name, description) VALUES (1, 'X', 'dup');

# 2. run 引用不存在的 dataset 被拒绝
# INSERT INTO runs (id, dataset_id, model, seed, status, created_at)
# VALUES (99, 999, 'CNN', 0, 'completed', '2026-09-17');

# 3. 同一 run 的重复指标被拒绝（UNIQUE(run_id, metric_name)）
# INSERT INTO metrics (run_id, metric_name, metric_value)
# VALUES (1, 'accuracy', 0.99);

# 预期：三条全部报 sqlite3.IntegrityError
```

> [!note] 约束是数据的“法律”
> 主键防重复身份，外键防孤儿引用，UNIQUE 防重复事实，CHECK 防非法值。
