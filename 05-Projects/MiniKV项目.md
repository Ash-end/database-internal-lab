# MiniKV：教学型持久化 KV 引擎（D9–D11 实现，D14 交付）

> 来源：教材第 7 章 Bitcask（书 153–154 页 = PDF 173–174 页，图 7-11）。

## 一句话设计

记录**追加**写日志文件；内存 `keydir` 记每个 key 的最新位置；
启动扫描日志重建索引；压实只留最新版。

## API 合同（待实现，D9 起）

```python
put(key: bytes, value: bytes) -> None
get(key: bytes) -> bytes | None   # 不存在 None，空值 b"" 不混淆
delete(key: bytes) -> None        # 删不存在的 key 不报错（墓碑）
close() -> None
compact() -> None                 # 离线压实
```

## 边界（先定死，不发散）

- 单进程独占、串行调用、单数据日志、离线压实。
- keydir 只存 key 和偏移，不存 value。
- 不做：SQL 解析、MVCC、多线程、分布式、Raft、Web。
- 日志即主存储，不另叠 WAL/memtables/SSTable（D8 WAL 实验独立）。
- 不包装 sqlite3/dbm/shelve；不用 pickle 代替二进制编码（D6 先练编码）。

## 失败模型（先想好再写码）

- 末尾未完成记录：恢复到最后完整边界，处理残留尾部后才能再写。
- 中间损坏（非法标识/长度/校验错）：明确报错，不静默跳过。CRC 只检错不纠错。
- 写入/同步错误：不返回成功；定好出错后禁写直到重开检查。
- 压实：停读写 → 写临时文件 → 检查同步 → 发布 → 重建索引；未完成临时文件永不转正。

## 必做测试（12 项，D11–13，G3 门）

- [ ] put/get、键不存在、空 bytes；中文、长值、非法类型与长度。
- [ ] 覆盖读最新；删除重启不复活；多次开关一致。
- [ ] 尾部截断恢复与后续写入；完整记录校验错明确报错。
- [ ] 写入/同步错误不返回成功。
- [  ] 压实前后及重启一致；临时文件未完成不转正；发布前后中断点。
- [ ] 10000 次固定种子随机对照（含更新删除重启）。
